# 端到端测试清单（E2E）

从**空白环境**走完一遍完整流程：首次运行引导 → 导入 3 个 Skill → 启用 2 个 →
映射校验 → 同步 GitHub → 导出。

**这份清单是给人执行的手工脚本，不是自动化测试。** 自动化测试在
`src-tauri/tests/` 与各模块的 `#[cfg(test)]` 里，它们证明"代码按预期工作"；
本清单要证的是另一件事：**一个真实的人，在真实的机器上，能不能走通这条路**。

编写方式遵循项目里反复吃过亏的那条教训：
**每一项都写成可操作的动作**（"点 X，观察 Y"），而不是只写预期结果（"面板可用"）。
曾经正是因为只写了预期结果，漏掉了"详情面板宽度可拖拽"，缺陷由用户在实际使用中发现。

---

## 0. 准备一个干净的环境

**这一步不能跳过**——在已有配置的机器上跑，走不到"首次运行"的路径。

### 0.1 移开现有配置

配置在 `%APPDATA%\BakaSkill\`。**移开而不是删除**（做完可以搬回来）：

```powershell
# 关闭 BakaSkill
Get-Process bakaskill -ErrorAction SilentlyContinue | Stop-Process -Force

# 把配置目录改名移开（不删除）
Rename-Item "$env:APPDATA\BakaSkill" "BakaSkill.bak-$(Get-Date -Format yyyyMMdd-HHmmss)"
```

同步工作区在 `%LOCALAPPDATA%\BakaSkill\sync\`，**可以留着**——
它是从仓库可重建的副本，不影响本清单的判定。

### 0.2 准备一个空的中央库位置

新建一个空文件夹，例如 `D:\E2E-Library`。**不要用 `_demo_library` 或
`_perf_library`**——那两个是测试与基准造的临时目录，里面已有内容，
会遮住"中央库为空"这一步。

### 0.3 准备 3 个待导入的 Skill

新建一个文件夹 `D:\E2E-Import`，在里面放三个子目录，每个含一个 `SKILL.md`：

```
D:\E2E-Import\
├─ alpha-notes\SKILL.md
├─ beta-tools\SKILL.md
└─ gamma-lint\SKILL.md
```

每个 `SKILL.md` 建议写成这样（内容会用于后面的搜索检查）：

```markdown
---
name: alpha-notes
description: 用于测试的示例技能甲
tags: [测试, 示例]
---

# alpha-notes

这是一段用于全文搜索测试的正文，包含一个专属标记 ALPHA_MARK_9231。
```

三份分别用不同的标记：`ALPHA_MARK_9231` / `BETA_MARK_9231` / `GAMMA_MARK_9231`。
**记录下这三个词**，第 5 步要用。

## 1. 首次运行引导

| # | 动作 | 观察什么 | 结果 |
| --- | --- | --- | --- |
| 1.1 | 启动应用 | 弹出「欢迎使用 BakaSkill」，顶部有三个步骤指示：选择中央库 / 连接 Agent / 启用第一个 Skill | ☐ |
| 1.2 | 点「选择文件夹…」，选 `D:\E2E-Library` | 出现该位置的体检结论：文件系统（应为 NTFS）、卷类型、可用空间，以及"这个位置可以用作中央库" | ☐ |
| 1.3 | 点「创建并设为中央库」 | **引导不会消失**，窗口切到第 2 步；`D:\E2E-Library` 下出现 `skills\` 与 `.bakaskill\` 两个目录 | ☐ |
| 1.4 | 看第 2 步的 Agent 列表 | 每个 Agent 显示状态：绿勾=已就绪、黄色三角=已安装但技能目录不存在、灰色=未检测到安装。已就绪的显示其技能目录绝对路径 | ☐ |
| 1.5 | 若某个 Agent 显示「已安装，但技能目录还不存在」，点它的「创建目录」 | 该行变为绿色"已就绪"，并显示目录路径；到资源管理器里确认该目录已真实存在 | ☐ |
| 1.6 | 点「下一步」 | 进入第 3 步；因为中央库是空的，显示「中央库还是空的」+「导入 Skill…」按钮 | ☐ |
| 1.7 | 点「导入 Skill…」 | 弹出导入向导（与主界面的是同一个） | ☐ |

> **1.6 是关键一项**：如果第 3 步在没有 Skill 时只给一句"稍后再说"，
> 真正的首次运行就走不通——这正是把它做成"能就地导入"的原因。

## 2. 导入 3 个 Skill

| # | 动作 | 观察什么 | 结果 |
| --- | --- | --- | --- |
| 2.1 | 在导入向导里选「文件夹」，选 `D:\E2E-Import` | 出现预览：3 个候选（alpha-notes / beta-tools / gamma-lint），无冲突、无非法项 | ☐ |
| 2.2 | 确认导入 | 提示"已导入 3 个 Skill"；`D:\E2E-Library\skills\` 下出现三个目录，每个含 `SKILL.md` | ☐ |
| 2.3 | 再次打开导入向导，**再导一次同一个文件夹** | 3 项全部被标记为**同名冲突**；默认动作是**跳过**（不是覆盖） | ☐ |
| 2.4 | 把其中一项的动作为「替换」，确认导入 | 提示成功；被替换的那份**被移到一旁**（目录名带 `.replaced-<时间戳>`），**没有被就地删除** | ☐ |
| 2.5 | 关闭对话框，返回主界面 | 列表显示 3 个 Skill；**引导窗口此时应该已经结束**（若还停在第 3 步，点「完成」） | ☐ |

> **2.3 与 2.4 是导入的两条安全线**：默认不动用户已有的东西；替换是"移走"而不是"销毁"。

## 3. 启用 2 个 Skill

先确认至少有一个 Agent 处于「已就绪」（否则回第 1.5 步创建目录）。

| # | 动作 | 观察什么 | 结果 |
| --- | --- | --- | --- |
| 3.1 | 在主界面的搜索框输入 `ALPHA_MARK_9231` | 列表只剩 alpha-notes 一个；命中的正文片段**高亮**显示 | ☐ |
| 3.2 | 再输入 `tag:测试` | 列表只剩带该标签的 Skill；搜索框下方出现 `tag:测试` 的筛选 chip | ☐ |
| 3.3 | 清空搜索 | 列表恢复 3 个 | ☐ |
| 3.4 | 勾选 alpha-notes 与 beta-tools（**不勾** gamma-lint） | 底部出现批量操作栏，显示"已选 2 项" | ☐ |
| 3.5 | 点「全部启用」 | 提示成功；**若部分失败，必须逐条说明是哪个 Agent 为什么失败**（不能只说"部分失败"） | ☐ |
| 3.6 | 打开资源管理器，进到该 Agent 的技能目录 | 出现 `alpha-notes` 与 `beta-tools` 两个条目；**右键 → 属性**，应显示为"链接"（junction）而非普通文件夹 | ☐ |
| 3.7 | 双击进入 `alpha-notes`，打开 `SKILL.md`，随便改一个字并保存 | 到 `D:\E2E-Library\skills\alpha-notes\SKILL.md` 查看，**改动已同步**（同一份数据） | ☐ |
| 3.8 | 回到应用，**单独启用 gamma-lint**（只勾它 → 全部启用） | 3 个都已接入 | ☐ |

> **3.6 与 3.7 是"链接真的生效了"的直接证据**，只看界面上的绿点是看不出来的。

## 4. 映射校验

| # | 动作 | 观察什么 | 结果 |
| --- | --- | --- | --- |
| 4.1 | 左侧导航点「映射矩阵」 | 出现 Skill × Agent 矩阵；**页面上明示中央库根路径与每个 Agent 技能目录的绝对路径** | ☐ |
| 4.2 | 逐格核对（抽样 10 格） | 每一格的状态与资源管理器里的实际情况**一致**：有链接=实心圆、没有=空心圆 | ☐ |
| 4.3 | 鼠标悬停在一个"已接入"的格子上 | 提示中同时给出**中央库目标路径**与 **Agent 链接路径** | ☐ |
| 4.4 | 用资源管理器**手动删掉**某个 Agent 目录里的链接（右键 → 删除） | 回到应用点「刷新校验」，该格变成**断链**（⚠） | ☐ |

## 5. 同步 GitHub

需要一个 GitHub 仓库。**推荐用空仓库**；若用已有内容的仓库，
注意观察 5.5 那条（仓库原有内容不被破坏是本项目的核心承诺）。

| # | 动作 | 观察什么 | 结果 |
| --- | --- | --- | --- |
| 5.1 | 设置页 → GitHub 同步 → 绑定仓库 | 提示"已绑定仓库：…" | ☐ |
| 5.2 | 点「同步到仓库」 | 提示同步成功 | ☐ |
| 5.3 | 到 github.com 打开该仓库 | 出现 `skills/alpha-notes/SKILL.md` 等 3 个 Skill；**提交信息里中文名没有被转义成 `\344\270\255` 这样的八进制** | ☐ |
| 5.4 | 在中央库改一个 SKILL.md，回应用再点「立即同步」 | 远端该文件内容随之变化 | ☐ |
| 5.5 | **若用的是已有内容的仓库**：看仓库原本的文件 | 原样还在，**既没被删除、也没出现在新提交里** | ☐ |
| 5.6 | 在 GitHub 网页上新建 `skills/网页新建/SKILL.md`，回应用点「取回缺失的 Skill」 | 提示"已取回 1 个 Skill"；左侧列表出现"网页新建" | ☐ |
| 5.7 | 把本地某个 Skill 内容改得与远端**不同**，再点「取回缺失的 Skill」 | 提示"仓库里没有中央库缺少的 Skill"；**本地那份内容不变**（不覆盖） | ☐ |
| 5.8 | 断网（或把仓库地址改成一个不存在的地址）后点「同步到仓库」 | 出现**可读的中文提示**（"无法访问该仓库…"之类），不是英文 git 原始输出；中央库文件不受影响 | ☐ |

## 7. 安装与卸载（**只能由人执行**）

这一步要用 `pnpm tauri:build` 产出的安装包，在**真实安装**的前提下做。

| # | 动作 | 观察什么 | 结果 |
| --- | --- | --- | --- |
| 7.1 | 双击 `src-tauri/target/release/bundle/nsis/*.exe` | SmartScreen 提示"未知发布者"（未签名，属预期）；点「更多信息 → 仍要运行」可继续 | ☐ |
| 7.2 | 完成安装并启动 | 应用正常启动，能读到刚才配置的中央库 | ☐ |
| 7.3 | 从开始菜单卸载 | 卸载完成，安装目录被清除 | ☐ |
| 7.4 | **卸载后检查中央库** | `D:\E2E-Library` 下的 3 个 Skill **完好无损**——这正是本项目对用户的承诺 | ☐ |
| 7.5 | 卸载时**勾上**"删除应用数据"再卸一次 | 中央库仍然完好；`%APPDATA%\BakaSkill\config.json` 也仍然存在（原因见 `docs/DISTRIBUTION.md` §3.2） | ☐ |

> 7.5 是很多人会误判的一条：那个勾选框对 BakaSkill **不起作用**，
> 因为应用数据不在它要删的目录里。文档里写清楚了，这里实测确认一次。
